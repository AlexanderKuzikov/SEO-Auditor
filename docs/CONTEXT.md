# CONTEXT — SEO Auditor

> Живое состояние проекта. Обновлять в конце сессии.

## Что это

On-page аудит сайта: собственный краулер на стандартной библиотеке Python, ~40
проверок, снимок в JSON и diff между прогонами. Zero dependencies.

Чек-лист из двух слоёв: базовый (общий для Яндекса, Google, Bing — title, canonical,
заголовки, alt, robots, sitemap, CWV, hreflang) и слой специфики Яндекса (кириллица
в URL, типы Schema без rich results, пороги под обрезку в сниппете). Решение
зафиксировано в `DECISIONS.md`: «Яндекс вместо Google» — неверная рамка, база
общая, специфика добавляется сверху.

Взят как замена обёртке `AgriciDaniel/on-page-seo` (Firecrawl + DataForSEO, платные
API, привязка к Google). Оттуда взята идея таксономии чек-листа; код, краулер, diff
и слои специфики — свои.

## Проверенные находки на zavodsvay.ru

Полный прогон: **574 из 575 страниц за 117 секунд** (4 потока). Sitemap покрывает
весь сайт, «не в sitemap» — ноль.

Структура: **529 из 574 страниц — карточки `/objects/N/`**, 52–66 слов каждая.
Медиана текста 56 слов, p10 52, p90 66, p99 772 (это статьи). То есть 92% сайта —
однотипный каталог, и его SEO-вес определяется шаблоном карточки, а не статьями.

| Находка | Масштаб | Оценка |
|---------|---------|--------|
| **SCHEMA_INVALID** | **574 из 575** | разметка сломана на всём сайте: в `legalName` организации незаэкранированные двойные кавычки, `json.loads` падает |
| DUP_TITLE | 10 групп | дубли на карточках объектов |
| DUP_H1 | 11 групп | там же |
| DUP_DESCRIPTION | 8 групп | шаблонные описания |
| TITLE_LONG | 304 | title объектов 80–107 символов |
| Битый URL | 1 | разбирается вручную |
| Сирота | 1 | нет входящих внутренних ссылок |
| THIN_CONTENT | 0 | при пороге 45; при пороге 300 давал 546 ложных срабатываний |

Главный вывод: 574 страницы с неработающей разметкой — это первоочередная задача,
чинится за минуты, а эффект на все страницы сразу. Второй по важности риск —
шаблон карточки объекта (дубли и длинные title на 529 страницах).

## Прогон по сети (3 домена)

`sites.txt`: zavodsvay.ru, yamobur-vezdehod.ru, ubm.ru.

| Домен | Источник URL | ok | Битые | Топ проблемы |
|-------|--------------|----|-------|--------------|
| zavodsvay.ru | sitemap (24) | 24 | 1 | SCHEMA_INVALID на всех — сломанный JSON-LD |
| yamobur-vezdehod.ru | sitemap (11) | 11 | 0 | NO_CANONICAL, HREFLANG_INCOMPLETE (есть hreflang, нет x-default) |
| ubm.ru | bfs (6) | 6 | 0 | NO_CANONICAL; **sitemap.xml недоступен**, robots без директивы Sitemap |

ubm.ru требует внимания: sitemap отдаёт ошибку, покрытие получено обходом с главной,
то есть неполное. Нужен рабочий sitemap либо свой список URL через `--urls`.

## Решения, которые важно помнить

- Отдельный репозиторий, а не модуль `SEO-Zavodsvay`: инструмент нужен для сети
  доменов, лежать в проекте одного клиента не может. Подробно в `DECISIONS.md`.
- Повторный прогон в тот же день архивируется, а не затирает снимок — иначе diff
  не имеет предыдущей точки и история теряется.
- Снимки разложены по хостам: один файл на домен в сети из пяти перетирал бы данные.
- `alt=""` у счётчика аналитики и ссылка-иконка с картинкой не считаются дефектами —
  иначе на каждом сайте будет систематический ложный шум.

## Open-проблемы

- `Crawl-delay` из robots.txt не читается, пауза фиксированная. Для чужих крупных
  сайтов прогон может быть навязчивым. Порог: ~1000 URL на домен.
- Контент отдаётся `http`-ссылками в части снимков — отдельная проверка
  «адреса в sitemap указаны в https» ещё не сделана, ловится через `REDIRECT_SCHEME`.
- Порог `THIN_WORDS = 300` не калиброван на конкретные тематики. Для локального
  коммерческого сайта 250 слов может быть нормой.
- Нет проверки «страницы из sitemap, которых нет на сайте» — сейчас ловится
  косвенно через битые URL.
- Markdown-отчёт для заказчика не генерируется: по решению владельца не нужен,
  снимка и сводки в консоли достаточно.
- `TITLE_MAX = 70` даёт 304 срабатывания на объектах zavodsvay.ru. Порог взят под
  обрезку сниппета, но для шаблонных title объектов его надо откалибровать под
  конкретный шаблон, иначе сигнал шумит.
