# DECISIONS — SEO Auditor

> ADR, append-only. Новое решение — в конец, с датой.

---

## 2026-09-30 — Отдельный репозиторий, а не модуль SEO-Zavodsvay

**Контекст.** Инструмент написан и отлаживается в `SEO-Zavodsvay`: там лежат
`webmaster_baseline.py`, `webmaster_monitor.py`, ядра сети, папка `audits/`.
Казалось бы, место готовое.

**Решение.** Отдельный репозиторий `SEO-Auditor`.

**Почему.**
- Инструмент generic: URL сайта — обязательный аргумент, ничего не зашито под
  zavodsvay. А нужен он для всей сети доменов (pirs, yamobur, ubm, gefest) и для
  статических сайтов вне сети. Лежа в `SEO-Zavodsvay`, он использовался бы из чужих
  репозиториев — прямое нарушение правила «не выходить за пределы проекта».
- Разные контуры данных: `audits/` SEO-Zavodsvay уже держит ручной маркетинговый
  аудит и снапшот Вебмастера. Третий, машинный, артефакт в той же папке без общего
  смысла.
- Разный ритм жизни: SEO-Zavodsvay живёт циклами Wordstat/ядро, аудитор — циклами
  «деплой → перепроверка».

**Цена.** Ещё одна папка в коллекции и церемония документации ради ~900 строк кода.
Принимается: окупается сетью доменов.

**Альтернатива, отклонённая.** Git submodule или пакет в общем репозитории — сложнее
поддерживать, чем просто свой репозиторий.

## 2026-09-30 — Zero dependencies, один монолитный файл

**Контекст.** На рынке есть готовые решения на BeautifulSoup + aiohttp, есть
обёртки над платными API.

**Решение.** Только стандартная библиотека: `urllib` для сети, `html.parser` для
разбора, `concurrent.futures` для потоков. Всё в одном файле `onpage_audit.py`.

**Почему.**
- Свой чек-лист вместо платного API: DataForSEO и Firecrawl не дают Яндекс-сигналов,
  стоят денег и требуют зарубежной оплаты с российских карт.
- `html.parser` достаточно: нужен фиксированный набор тегов и атрибутов, а не
  произвольный HTML. Регулярками по тегам такой разбор ломается на вложенности.
- Монолит копируется на любой сервер одной командой, ничего не ставится.
- `SEO-Zavodsvay` уже задал конвенцию zero-dep, отступление от неё было бы
  расколом.

**Цена.** Нет CSS-селекторов и отказоустойчивости промышленного парсера. Оправдано:
для аудита on-page HTML предсказуем, а при необходимости точность повышается точечно.

**Следствие.** При росте функций (структурный аудит, отчёты) репозиторий придётся
разбить на модули. Это осознанное решение на будущее, не сейчас — YAGNI.

## 2026-09-30 — Diff прогонов как основная ценность

**Контекст.** Обычные on-page аудиторы выдают разовый отчёт. Заказчику нужен ответ
на вопрос «что стало лучше или хуже после работ».

**Решение.** Снимок по дате плюс diff двух прогонов: изменившиеся метрики постранично,
дельты счётчиков проблем, сводные показатели, добавленные и исчезнувшие URL.

**Почему.** Референсный инструмент такого не умеет вообще. Для миграций и правок
сайта дельта — то, что реально показывает заказчику результат, а не список
пожеланий.

**Три обязательных свойства, без которых фича бесполезна:**
1. Страница определяется по ключу `host + путь` **без схемы** — иначе `http` и
   `https` одной страницы считаются разными.
2. Признак редиректа считается **с учётом схемы** — иначе редирект http→https,
   самый частый дефект сайтов, невидим.
3. Повторный прогон в тот же день архивируется с меткой времени, а не затирает
   снимок — иначе предыдущей точки сравнения не существует.

## 2026-09-30 — Чек-лист под Яндекс, а не под Google

**Контекст.** Таксономия бралась из DataForSEO `on_page` — она Google-ориентирована.

**Решение.** Пороги и набор проверок адаптированы под Яндекс.

**Почему.**
- Open Graph не влияет на выдачу Яндекса — понижен до `info`, не `warn`.
- `FAQPage` и `HowTo` не дают rich results: на Яндексе они только семантика — помечены
  как `DEAD_SCHEMA`, не как «добавьте разметку».
- Кириллица в URL и подчёркивания — дефект под Яндекс, а не формальность.
- Длины title/description заданы под обрезку в сниппете, а не под формальные
  рекомендации Google.

**Следствие.** Данных Яндекса здесь нет — только статический разбор страницы.
Реальные CTR, позиции и индексация живут в `SEO-Zavodsvay` через Вебмастер API.
Инструменты не дублируют друг друга, а закрывают разные половины.
