# SEO Auditor — Instructions for AI Agents

## Commands
- audit: `python onpage_audit.py <site-url> [--limit N] [--diff] [--urls FILE] [--psi] [--out FILE]`
- network: `python onpage_audit.py --all sites.txt [--limit N] [--diff]` — сводка по всем доменам + регрессии
- compare: `python onpage_audit.py --compare OLD.json NEW.json`
- self-check: `python onpage_selfcheck.py` — единственный тест, гонять после любой правки

## Conventions
- **Zero dependencies.** Только стандартная библиотека Python. Не предлагать bs4, lxml, requests, httpx, pandas — это ломает главное свойство проекта.
- Python 3.9+ синтаксис (`dict | None` в аннотациях), вызов `python`, не `python3`.
- Один файл = один инструмент. Не разбивать на пакет без запроса: `onpage_audit.py` сознательно монолит, его можно скопировать на любой сервер.
- Код и идентификаторы — английский, сообщения пользователю и коды проблем — русский. Вывод в консоль переводить в UTF-8 (`sys.stdout.reconfigure`).
- Снимки — `audits/<host>/onpage-<YYYY-MM-DD>.json`. Повторный прогон в тот же день архивируется как `onpage-<YYYY-MM-DD>-<HHMMSS>.json`, не затирает предыдущий.
- `sites.txt` — список доменов сети, по одному в строке, без `https://`, комментарии через `#`. Настройки домена пишутся после `#` через пробел: `thin-words`, `limit`, `psi`. Файл коммитится: это конфигурация, а не данные.
- Секреты только из окружения: `PSI_API_KEY`. В `.env` проекта ключей не хранить, файл не нужен.

## Structure
- `onpage_audit.py` — краулер, парсер, чеки, снимок, diff
- `onpage_selfcheck.py` — самопроверка парсера, чеков и diff на фикстурах в коде
- `sites.txt` — домены для `--all`
- `audits/<host>/` — снимки и diff-прогоны по датам
- `docs/CHECKS.md` — список проверок с кодами и порогами (правится при добавлении чека)

## Adding a check
1. Добавить код в константу/логику и запись в `add(level, code, msg, fix)`.
2. Проверки, которые видно по одной странице, — в `analyze()`. По всему сайту (дубли, сироты, sitemap) — в `site_report()`.
3. Код добавить в `WATCH`, если метрика должна попадать в diff.
4. Покрыть в `onpage_selfcheck.py` — иначе регрессия не заметна.
5. Внести в `docs/CHECKS.md`.

## Do NOT touch
- `audits/` — снимки заказчиков не переписывать вручную, только перегенерировать
- Пороги в константах без обоснования в `docs/DECISIONS.md`: они влияют на трактовку отчёта
- `onpage_selfcheck.py` — фикстуры `GOOD`/`BROKEN` должны оставаться противоположными по чистоте

## Питфоллы
- **Google не выкидывать.** Базовый слой чек-листа общий для всех поисковиков, Core Web Vitals кросс-поисковиковые (инициированы Google, используются Bing). Формулировки вида «влияет только на Яндекс» или «влияет только на Google» — признак неверной рамки, перепроверять. Специфика добавляется слоем, а не вычитанием.
- **Проверяй свои же находки на сырье.** Ложные срабатывания дороже пропусков: `alt=""` у счётчика Яндекса — не дефект, ссылка-иконка с картинкой — не пустой анкор, а битый JSON-LD на сайте — настоящая находка, даже если «должно работать».
- `Crawl-delay` из robots.txt не читается, пауза фиксированная (`DELAY`). Для чужих крупных сайтов — увеличить или не запускать.
- PSI без ключа отдаёт 429. Ошибка пишется в снимок, прогон не падает. Ключ бесплатный, берётся в Google Cloud Console.
- CrUX field data есть не для всех URL — при отсутствии остаётся только lab LCP, это отмечается флагом `field: false`. Это норма, а не дефект.
- Порог `EMPTY_ANCHOR > 2`: одна-две пустые ссылки — норма, дефектом считается систематическое отсутствие анкоров.
- **Сайт может не отвечать по HTTPS.** Раньше аудитор на таком домене молча возвращал «0 страниц». Теперь `ensure_reachable()` откатывается на HTTP и выдаёт `NO_HTTPS` как дефект: без TLS браузер помечает сайт небезопасным, поисковики не дают полного доверия.
- **Молчаливое усечение — худший дефект.** Снимок, собранный со среза, выглядит завершённым, а проверено 4% сайта. При срезе обязаны быть: предупреждение, `truncated` в снимке, `!` в сводке, и diff должен отказываться показывать регрессии.
- **Абсолютные пороги без калибровки дают шум.** `THIN_CONTENT = 300` на каталоге из карточек по 56 слов даёт сотни ложных warn. Пороги настраиваются на домен в `sites.txt`, а распределение p10/медиана/p90 печатается в сводке — сначала смотри на распределение, потом выбирай порог.
- **Правки в чужих репозиториях проверяй на окончания строк.** В `Zavodsvay-Static` `core.autocrlf=false`, репозиторий хранит ровно то, что на диске: запись файла в CRLF переписывает весь файл и превращает дифф в мусор. Перед коммитом смотреть `git diff --stat` — цифры должны быть пропорциональны сути правки.
